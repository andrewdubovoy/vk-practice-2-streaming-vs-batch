# Практическая №2 · Streaming vs Batch

Вариант №2 VK Education. Установка принимает синтетическую IoT-телеметрию, обновляет минутную витрину и пересчитывает суточные итоги.

- [Отчёт по форме преподавателя](отчет.md)
- [Схема](architecture.png) и [редактируемый исходник Draw.io](architecture.drawio)
- [Docker Compose](docker-compose.yml) и [журнал проверки](evidence/verification.log)

Нужен Docker с Linux Engine и Docker Compose. Выполняйте команды из папки проекта.

```bash
docker compose up -d --build --wait
docker compose ps
```

По умолчанию API слушает `127.0.0.1:18082`. Для наблюдения откройте [GET /metrics](http://127.0.0.1:18082/metrics). Метод `POST /events` принимает JSON с полями `event_id`, `sensor_id`, `event_time` (ISO 8601 с часовым поясом) и `value` (целое число). Ответ `202` означает запись входа в журнал. Дата до 1970 года или более чем на 5 минут в будущем отправляется обработчиком в карантин. При ответе `400` или `422` исправьте тело запроса. При сетевом сбое или ответе `503` повторите отправку с прежним `event_id`.

Сквозной сценарий запускается на **пустом томе**. Он проверяет ответы на некорректный JSON, отправляет граничную дату перед корректными событиями, повторяет контрольный набор и через `GET /metrics` ждёт автоматического исправления суточного итога. На Windows скрипт также останавливает потребителя, имитирует завершение до `COMMIT`, проверяет откат и запускает обработку снова.

```powershell
./verify.ps1
```

Для запуска основной проверки без PowerShell используйте `docker compose run --rm --build demo` после запуска стенда. Витрина batch обновляется после каждого цикла с паузой 10 секунд. Принудительный перерасчёт выполняется командой `docker compose exec -T ingest python app.py batch`.

`docker compose down` останавливает стенд, сохраняя именованный том. Для повторного чистого прогона задайте другое имя проекта через `COMPOSE_PROJECT_NAME` и свободный локальный порт через `VK_P2_PORT`.
